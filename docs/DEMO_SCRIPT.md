# ProjectBridge demo video script

**Target length:** 1 minute 45 seconds to 2 minutes  
**Format:** screen recording with voiceover; use the local release candidate, fictional data only, and a clean browser window.  
**Story:** turn the CS Club website idea into a reviewed team and a saved first plan.

| Time | Screen action | Narration |
|---|---|---|
| 0:00–0:10 | Show the landing page and ProjectBridge name. | “Student projects often start with a good idea, but it can be hard to see which skills the team still needs. ProjectBridge helps make those needs and tradeoffs visible.” |
| 0:10–0:25 | Choose **Start a project**, then **Use CS Club example**. Create the example project. | “I’ll use a fictional CS Club website project. The example gives us a consistent path to explore the product.” |
| 0:25–0:40 | Review the requirements and confirm them. | “Before matching begins, I can review the suggested requirements and confirm what this project actually needs.” |
| 0:40–1:00 | In **Choose your mix**, show team coverage and Missing Piece. Open **Why?** on a candidate and pause on the explanation below that candidate. | “ProjectBridge compares fictional profiles against those needs. I can inspect the evidence for a candidate right where I’m making the choice. These scores are transparent heuristics, not probabilities of success.” |
| 1:00–1:18 | Add a candidate, then choose **Save my team**. Show the refreshed coverage and any remaining gap. | “I choose the people I want and save the team. The coverage view updates so I can see what is covered and what still needs attention.” |
| 1:18–1:42 | Open the roadmap, generate an editable draft, review it, and save. Change one task to **Done**, then refresh if time allows. | “From the confirmed team, I can draft an editable roadmap, review its tasks, and save it. Task progress stays with the project session.” |
| 1:42–1:55 | End on the saved roadmap or project name. | “The current demo uses fictional data and deterministic templates. It does not call a live AI provider, and its recommendations are there to support human review.” |

## Recording checklist

- Use a fresh demo session with only fictional example data; do not show the existing local database or real student information.
- Record at a readable desktop resolution. Keep the pointer still while explaining a screen and let the candidate explanation remain visible long enough to read.
- Capture clean screenshots separately: landing page, candidate explanation/team coverage, and saved roadmap.
- Hide browser developer tools, terminal windows, machine paths, account details, notifications, and unrelated tabs.
- Ensure the narrated claims match the on-screen behavior. If a step takes longer, trim pauses rather than speeding up text or hiding review/confirmation actions.
- Play back the exported video once, check audio and text legibility, and verify the screenshots show the same release candidate.
